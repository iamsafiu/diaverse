  Моя рекомендация: Вариант C

  Вот почему. Ключевая идея — слой абстракции в одном файле:

  ┌─────────────────────────────────────────────────────────┐
  │  Компоненты (ShopPage, GradeCard, PetGrid, etc.)       │
  │  Не знают откуда данные. Работают с ShopCatalog.        │
  ├─────────────────────────────────────────────────────────┤
  │  types.ts — единый контракт: ShopCatalog, ShopSection,  │
  │  ShopItem, PurchaseIntent                               │
  ├─────────────────────────────────────────────────────────┤
  │  api.ts — ЕДИНСТВЕННОЕ место, которое знает             │
  │  про реальные эндпоинты                                 │
  │                                                         │
  │  Phase 1:  fetchShopCatalog() {                         │
  │              const [market, pets, boxes] =               │
  │                await Promise.all([                       │
  │                  apiClient.get("/market"),               │
  │                  apiClient.get("/characters/store"),     │
  │                  apiClient.get("/loot_boxes"),           │
  │                ]);                                       │
  │              return normalize(market, pets, boxes);      │
  │            }                                            │
  │                                                         │
  │  Phase 2:  fetchShopCatalog() {                         │
  │              return apiClient.get("/v1/cabinet/shop");   │
  │            }                                            │
  │                                                         │

  Почему это безопасно

  РИСК-МАТРИЦА

                          Бот     Мобилка    Веб
                          ─────   ───────    ────
  Вариант A (fat client)   ✅       ✅         ⚠️  (хрупкий фронт)
  Вариант B (facade)       ✅       ✅       ✅  (но ждём бэк)
  Вариант C (гибрид)       ✅       ✅       ✅  (сейчас + потом)

  Что может сломаться при варианте C:

  Бот/мобилка:  НИЧЕГО — мы только ЧИТАЕМ существующие
                эндпоинты, не меняем их

  Веб шоп:     Если бэк изменит ответ /characters/store →
               ломается ТОЛЬКО normalize() в api.ts →
               фиксим в одном месте

  Покупки:     Пока не подключены — нет риска двойных
               списаний, потерянных транзакций и т.д.

  Про types.ts — единый контракт

  Это ядро всей архитектуры. Компоненты работают ТОЛЬКО с этими типами:

  ShopCatalog
  ├── sections: ShopSection[]
  │   ├── id: "grades" | "passes" | "pets" | "crates" | ...
  │   ├── title: string
  │   ├── icon: string
  │   ├── currency: "usd" | "xdv" | "both"
  │   └── items: ShopItem[]
  │       ├── id: string
  │       ├── title: string
  │       ├── description: string
  │       ├── image: string
  │       ├── price: { usd?: number, xdv?: number }
  │       ├── owned: boolean
  │       ├── locked: boolean
  │       ├── lockReason?: string
  │       └── metadata: Record<string, unknown>  ← grade bonuses,
  │                                                 pet class, etc.
  ├── userGrade: number
  └── userBalance: { xdv: number, dia: number }

  Откуда бы ни пришли данные (5 эндпоинтов или 1 фасад) — компоненты видят один и тот же ShopCatalog. Это и есть защита от рисков.

Вопросы, от которых зависит финальный набор

1. Скины — что продаётся?
   В бэке есть Character.subkind (halloween, christmas, asia, hippie, symbiote) и item_type: "skin" в ивентовом магазине. Скины — это отдельные
   товары за деньги/XDV, или они только как бонус к грейдам и ивентам?

2. Ежедневные предложения — есть ли логика в бэке?
   В ShopType есть daily = TODO. Если не реализовано — этот блок можно:

- Убрать на Phase 1
- Или захардкодить как промо-баннер ("скидка на Grade 2 эту неделю")

3. Ресурсы / Бусты — продаются отдельно?
   В бэке бусты (boost_chest_speed, boost_pet_xp, etc.) и ресурсы (bullets, galaglue) существуют как типы, но я не нашёл их как отдельные товары в /market. Они приходят из шкатулок/фабрики/ивентов. Можно ли их купить напрямую?

4. Фабрика — в магазине или отдельная страница?
   Фабрика — это целая мини-игра (воркшопы, крафт, таймеры). Она не очень вписывается в "магазин". Может быть отдельным роутом /factory?
