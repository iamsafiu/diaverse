# Crypton Task Brief

ТЗ: Механика оффера Crypton для Diaverse (Web + App)
1. Общая концепция

Crypton — это редкий персональный оффер внутри Diaverse, который появляется пользователю случайным образом не чаще 1 раза в месяц и позволяет предложить свою цену за конкретную сущность.

Главная механика:
• Пользователь получает уникальный шанс купить сущность по собственной цене.
• Пользователь сам выбирает сущность.
• Пользователь сам предлагает цену.
• Система отправляет заявку в админку.
• Администратор подтверждает / отклоняет / меняет цену.
• Пользователь получает решение и ссылку на оплату.

Цель механики:
• создать ощущение редкого события;
• повысить удержание;
• стимулировать регулярные заходы в веб-версию;
• создать эффект “охоты” за оффером;
• увеличить конверсию в покупку сущностей.

2. Основная логика работы
2.1 Частота показа

Каждому уникальному пользователю оффер может приходить:
• не чаще 1 раза в 30 дней;
• в случайный день;
• в случайное время;
• только при активности пользователя на платформе.

Важно:
Crypton НЕ запускается массово одновременно для всех пользователей.

3. Логика появления оффера
3.1 Условия показа

Оффер может появиться если:
• пользователь авторизован;
• прошло ≥ 30 дней с прошлого показа;
• пользователь находится на сайте;
• пользователь провел на сайте ≥ 10 секунд;
• оффер еще не был показан в текущем месячном цикле.
оффер имеет приоритет над модалкой со скидкой из магазина

3.2 Рандомизация

Система должна:
• ежедневно проверять пользователей;
• случайным образом выбирать день показа;
• случайным образом выбирать время показа.

Пример:
Пользователь может получить оффер:
• 3 мая;
• 17 мая;
• 28 мая.

Время тоже случайное:
• 13:12;
• 09:03.
НО! Важно! Оффер не надо показывать после 20:00 вечера. То есть показывать оффер или нет - определеяется по таймзоне пользователя.

5. Процесс подачи заявки
Этап 1 — выбор сущности

Пользователь видит:
• поиск;
• категории;
• сущности;
• evolutions;
• pets;
• ресурсы;
• предметы и т.д.

Формат:
search + dropdown/autocomplete.

Этап 2 — выбор количества

Если сущность допускает количество:
• пользователь указывает количество.

Пример:
• 1 pet;
• 500 crystals;
• 3 evolution shards.

Этап 3 — предложение цены

Пользователь вводит свою цену.

Важно:
Для каждой сущности есть допустимый диапазон.

Пример таблицы:

Тип сущности	Мин	Макс
Common Pet	$5	$15
Rare Pet	$15	$30
Epic Pet	$30	$50
Legendary	$50	$100

Если цена вне диапазона:
• форма не отправляется;
• выводится предупреждение.

7. Админка
7.1 Заявка

В админке отображается:
• пользователь;
• сущность;
• количество;
• предложенная цена;
• рыночная цена;
• рекомендуемая цена системы.

7.2 Кнопки действий
1. Approve

Подтвердить цену пользователя.

2. Reject

Отклонить заявку.

3. Counter Offer

Указать свою цену.

Пример:
Пользователь предложил:
$20

Администратор выставил:
$34

8. Автоматизация цены (следующий этап)

Вот как лучше автоматизировать механику.

8.1 Базовая рыночная цена

У каждой сущности есть:
base_market_price

Пример:
Legendary Pet = $100

8.2 Процент минимального допуска

Система определяет:
насколько предложение ниже рынка.

Пример:
• рынок = $100
• пользователь предложил $70
• отклонение = -30%

8.3 Логика автоодобрения
Авто APPROVE

Если:
цена ≥ 80% рынка

Пример:
• рынок $100
• пользователь дал $85
→ автоодобрение.

Auto Counter Offer

Если:
цена 40–79% рынка.

Формула:
counter_price = user_price × 1.6

Пример:
• пользователь $20
• система → $32

или:

counter_price = midpoint(user_price, market_price)

Пример:
• $20 и $100
→ $60.

Но лучше первый вариант:
он проще и эмоционально понятнее.

Auto Reject

Если:
цена < 40% рынка.

Пример:
• рынок $100
• пользователь дал $15
→ отказ.

9. Рекомендуемая модель (важно)

На первом этапе:
НЕ делать полную автоматизацию.

Лучший вариант:
• система считает рекомендуемую цену;
• админ просто нажимает кнопку.

То есть backend показывает:

“Рекомендуемая цена: $34”

И админ:
• подтверждает;
• меняет;
• отклоняет.

Это даст:
• быстрое тестирование;
• сбор статистики;
• понимание психологии игроков;
• обучение будущего алгоритма.

Ограничения

• 1 активная заявка на пользователя;
• 1 оффер в 30 дней;
• нельзя редактировать заявку после отправки;
• нельзя отправлять повторно после reject;
• сущности можно ограничивать по количеству.

    cache: "no-store",

    },

  console.log(r.status, state);
