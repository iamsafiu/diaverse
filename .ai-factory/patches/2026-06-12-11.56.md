# Raid auto-dispatch flag missing from manual starts

**Date:** 2026-06-12 11:56
**Files:** diaweb/frontend/modules/raids/components/RaidLocationStack.tsx, diaweb/frontend/modules/raids/components/RaidPetSelectionSummary.tsx
**Severity:** medium

## Problem

Auto-dispatch could be enabled in the raids UI, but manual raid starts did not send the `auto_dispatch` flag to the backend. As a result, one-pet starts and "send all" starts used the normal entry price instead of the auto-dispatch surcharge. The pet selection summary also did not show the surcharge.

## Root Cause

The auto-dispatch toggle kept its optimistic state inside the slots sheet, while `RaidLocationStack` owned the actual raid start command. The start command only knew the server setting from the last loaded state and never added `autoDispatch` to `RaidStartInput`.

## Solution

Moved the effective auto-dispatch state to `RaidLocationStack`, passed it down to the slots sheet and pet picker, and added `autoDispatch: true` to XDV start commands when the setting is active. The pet selection summary now displays the base XDV price plus the 20% surcharge as a separate colored amount and checks balance against the total.

## Prevention

When a child component controls a setting that affects command payloads, keep the effective state at the command owner level or pass the state change back before the command can run. UI price previews should use the same flags that will be submitted to the API.
