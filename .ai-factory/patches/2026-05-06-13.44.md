# Shop category modal height and guest offer visibility

**Date:** 2026-05-06 13:44
**Files:** diaweb/frontend/modules/shop/components/shopSections.module.css, diaweb/frontend/modules/shop/hooks/useShowcaseOffers.ts, diaweb/frontend/__tests__/modules/shop/useShowcaseOffers.test.tsx
**Severity:** medium

## Problem

Desktop shop category modals could grow nearly to the full viewport height, making the category overlay taller than the requested visual limit. Category deal showcase offers inside pet and skin sections were also hidden in guest mode when the backend marked them as not directly purchasable.

## Root Cause

The desktop modal used `max-height: calc(100vh - 36px)` with no fixed design cap. The showcase hook filtered backend category deal slots with `slot.canPurchase && !slot.owned`; guest slots are intentionally returned with `can_purchase=false` and a login-required style lock, so the frontend removed them before rendering.

## Solution

The modal now caps at `min(576px, calc(100vh - 36px))`, and the modal content is allowed to flex and scroll within that cap. Category deal showcase filtering now excludes only owned slots, so locked guest-visible offers still render while their purchase button remains disabled by the existing item and offer state.

## Prevention

- Treat visibility and purchase eligibility as separate concerns in shop UI code.
- For guest storefront behavior, test locked-but-visible offer states rather than only purchasable states.
- Keep modal height constraints on the shell and ensure inner content is the scroll container.
