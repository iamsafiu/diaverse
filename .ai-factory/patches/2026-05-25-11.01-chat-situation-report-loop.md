# Chat situation report duplicate sends and weak fallback

**Date:** 2026-05-25 11:01
**Files:** `aibot/app/application/use_cases/chat_situation_report.py`, `aibot/tests/test_chat_situation_report.py`
**Severity:** high

## Problem

The daily "Обстановка в чате" report repeatedly sent weak Telegram messages like "Сигналов недостаточно" even though source ingest had 110 recent messages.

## Root Cause

The scheduler reused the daily report row but did not treat `sent` as a terminal artifact state when the related job was no longer active. It kept enqueueing new jobs for the same report date. Separately, malformed LLM JSON was converted to an empty object, losing useful raw model output and producing a generic fallback mood.

## Solution

Treat sent/ready/source-not-ready report states as reusable artifacts and skip generation for already sent reports with a Telegram message id. Recover JSON from raw text when possible, use raw text as a fallback report instead of an empty placeholder, and block unusable "insufficient signal" reports when there are enough recent messages. Compact the Telegram formatter by removing the "Что отвечать" block and adding short recommendations.

## Prevention

Daily scheduled jobs must define terminal artifact states explicitly, not only active job states. For LLM JSON workflows, malformed JSON should preserve recoverable raw content and have a quality gate before external delivery. Telegram delivery tests should cover duplicate prevention and compact formatting.
