# Character fulfillment ignored quantity greater than one

**Date:** 2026-06-10 11:38
**Files:** `diaverseapi/app/cabinet/fulfillment/handlers.py`, `diaverseapi/tests/test_cabinet_fulfillment_service.py`
**Severity:** high

## Problem

A Crypton user bought two `Кибер Дракон` pets with selected evolution `E6`, but only one pet appeared in the vivarium. Production data showed the Crypton request and fulfillment line correctly stored `quantity = 2`, while only one `user_characters` row was created.

## Root Cause

The shared `grant_character_handler` ignored `FulfillmentLineInput.quantity` and called `grant_user_character` exactly once. Other multi-unit handlers such as loot boxes and vouchers already looped over quantity, but character grants kept the old single-entity assumption. This affected Crypton and any support/shop flow that granted more than one character in a single fulfillment line.

## Solution

Updated `grant_character_handler` to grant one user character per requested quantity unit, reuse the same parsed evolution option for every grant, and return all created ids in `snapshot_json.granted_entity_ids` while preserving `result_entity_id` as the last created entity for compatibility. Added `[FIX:character-quantity]` logs around the grant start and completion.

The affected production Crypton request was manually backfilled with one additional `Кибер Дракон E6` using guarded SQL after verifying the expected quantity and current count.

## Prevention

Fulfillment handlers for entity-producing item types must explicitly define quantity semantics. When a handler returns a single `result_entity_id`, tests should still cover `quantity > 1` and assert all created entity ids are captured in `snapshot_json.granted_entity_ids`.
