# Starter walker pet visible in raid pet selection

**Date:** 2026-06-04 13:31
**Files:** `diaverseapi/app/raids/infrastructure/pet_gateway.py`, `diaverseapi/app/raids/services/state_service.py`, `diaverseapi/app/raids/tests/test_gateways.py`, `diaverseapi/app/raids/tests/test_state_service.py`
**Severity:** medium

## Problem

The default starter pet "Кибер Ходок" appeared in raid pet selection. This pet exists for every user at account creation and should not be a playable raid dispatch candidate.

## Root Cause

Raid state exposed all non-deleted pets in `available_pets`. The default walker pet is represented by `Character.kind == "walker"`, but raid selection did not apply the existing product convention that hides walker definitions from normal pet lists.

## Solution

Added a raid-supported-pet predicate that excludes `kind="walker"`. The state selector now filters walker pets out of `available_pets`, while the command gateway blocks direct start requests that try to submit a walker `user_character_id`.

## Prevention

Selection filters for user-owned pets should account for product-only/default character kinds, not just deletion and lock state. Command paths must enforce the same eligibility rules as UI selectors to prevent manual API bypasses.
