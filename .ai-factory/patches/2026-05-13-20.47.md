# Cabinet overlay and scroll compositing artifacts

**Date:** 2026-05-13 20:47
**Files:** diaweb/frontend/app/[lang]/layout.tsx, diaweb/frontend/modules/cabinet/components/CabinetLayout.tsx, diaweb/frontend/modules/cabinet-profile/components/ProfileStatisticsDashboard.tsx, diaweb/frontend/modules/shop/components/shopSections.module.css
**Severity:** medium

## Problem

User-facing cabinet pages could show browser-dependent visual artifacts while scrolling. The issue was most visible in profile views and could look like extra elements overlapping content. The cookie banner was intentionally excluded from the fix scope.

## Root Cause

Several low-level UI layers increased the chance of Chrome compositor artifacts or stale overlays:
- a full-screen decorative background layer was still able to participate in hit testing;
- the cabinet shell used `background-attachment: fixed` inside an already fixed full-screen element;
- profile date picker popovers stayed mounted when the user scrolled or resized the viewport;
- shop category overlays used z-index values below cabinet header and notification layers.

## Solution

The fix kept layout geometry and visuals stable:
- marked the global decorative background as `aria-hidden` and `pointer-events: none`;
- removed the redundant `background-attachment: fixed` from the already fixed cabinet background;
- closed the profile date picker on outside pointerdown, Escape, scroll, and resize;
- raised shop category overlay z-index above cabinet chrome while keeping it below higher-priority modals.

## Prevention

- Avoid `background-attachment: fixed` on nested or already fixed animated shells.
- Decorative full-screen layers should be non-interactive and hidden from assistive technology.
- Floating popovers should close or reposition on scroll and viewport resize.
- Review z-index changes against the existing overlay hierarchy before adding new modal layers.
