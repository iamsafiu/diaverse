# Factory map bottom navigation restore

**Date:** 2026-05-26 20:17
**Files:** diaweb/frontend/modules/cabinet/components/CabinetLayout.tsx, diaweb/frontend/modules/factory/components/FactoryShell.tsx
**Severity:** medium

## Problem

The factory map follow-up hid more cabinet chrome than requested. The user asked to remove only the top cabinet bar with logo/download/notifications, but the bottom navigation and footer were also removed from the main factory route.

## Root Cause

The fullscreen route branch treated all cabinet chrome as unwanted for the game map. That overcorrected the layout: topbar, footer, and bottom navigation were all gated by the same factory-route condition instead of handling only the topbar.

## Solution

Kept `CabinetTopbar` hidden on the exact factory map route, restored `BottomNav` and `CabinetFooter`, preserved the bottom safe area padding, and made `FactoryShell` use `h-full` so the map fills the available layout area instead of forcing its own viewport height.

## Prevention

- Match route-specific chrome changes to the exact requested chrome element.
- Add tests that distinguish topbar visibility from footer and bottom navigation visibility.
- When introducing fullscreen shells, keep persistent app navigation explicit instead of grouping all chrome under one condition.
