# Pay1Time checkout redirects reused legacy form host after Cricti migration

**Date:** 2026-04-28 15:43
**Files:** diaverseapi/app/integrations/pay1time/urls.py, diaverseapi/app/cabinet/payments/pay1time/service.py, diaverseapi/app/cabinet/offers/advent/service.py, diaverseapi/app/core/settings.py, diaverseapi/.env.example, diaverseapi/tests/test_cabinet_pay1time_callback.py, diaverseapi/tests/test_cabinet_advent_payments.py
**Severity:** high

## Problem

After Pay1Time migrated to `cricti.com`, checkout redirects could still send users to `https://sbp-pay-form.pay1time.com/sbp/...`, which returned `502 Bad Gateway`.

## Root Cause

The backend had only one Pay1Time API base setting and accepted hosted checkout URLs from provider responses as-is. Existing checkout reuse logic treated internal return URLs and `/pay/form/` URLs as stale, but it did not recognize the legacy hosted SBP domain `sbp-pay-form.pay1time.com`.

## Solution

Added Pay1Time URL helpers to detect legacy `pay1time.com` hosts, rewrite legacy checkout redirects to the configured Cricti checkout/API base, and mark stored legacy checkout URLs for provider reinitialization. The default Pay1Time API base and `.env.example` now use `https://cricti.com`, with optional `PAY1TIME_CHECKOUT_BASE_URL` for a separate hosted-form domain.

## Prevention

When a payment provider changes infrastructure domains, update both API base URLs and hosted checkout/form URL handling. Regression tests should cover provider responses and stored checkout sessions from legacy hosts, not only API request hosts.
