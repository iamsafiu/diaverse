# Auth-bot broadcast test send failed after deploy

**Date:** 2026-06-02 17:02
**Files:** `aibot/docker-compose.prod.yml`, `aibot/scripts/run_runtime.py`, `aibot/tests/test_runtime_volume_init.py`, `aibot/.env.example`, `docs/features/copywriting/auth-bot-broadcasts.md`, `docs/runbooks/copywriting-production-runtime.md`
**Severity:** high

## Problem

The staff copywriting Broadcasts tab showed "Не удалось отправить тест." when sending an auth-bot test broadcast.

The first production failure was a `PermissionError` while storing the uploaded broadcast image. After fixing the live volume ownership, the request reached Telegram delivery and failed again because the `auth` bot profile token was not configured in the copywriting runtime.

## Root Cause

The broadcast media directory was mounted as a new Docker named volume. Docker created that volume as `root:root`, while `copywriting-api` and `copywriting-worker` run as the non-root `copywriting` user. The Dockerfile chown did not apply because named volumes are mounted after image filesystem preparation.

The runtime configuration also documented "auth bot profile" generically but did not explicitly require `TELEGRAM_BOT_TOKEN_AUTH` for `COPYWRITING_BROADCAST_BOT_PROFILE=auth`, so the service had no token to resolve for the auth bot profile.

## Solution

Added a production `copywriting-volume-init` service that runs as root before API and worker and chowns the shared broadcast image volume. Added a `copywriting-volume-init` runtime role in `scripts/run_runtime.py` with `[FIX:auth-bot-broadcast-volume]` logs for start, failure, and completion.

Updated the `aibot` env example and workspace docs to explicitly list `TELEGRAM_BOT_TOKEN_AUTH` for auth-bot broadcasts. The live runtime env was updated without printing the token, then API and worker were recreated. A direct internal smoke test returned `200` and delivered a test photo through the auth bot profile.

## Prevention

- Any new non-root Docker named volume must have an init/chown path in production compose, not only Dockerfile ownership.
- Profile-based Telegram sends must document the exact env variable resolved by the profile.
- Broadcast smoke must include both image storage and Telegram profile token resolution.
- Add tests for compose/runtime init contracts when Docker itself is not available locally.
