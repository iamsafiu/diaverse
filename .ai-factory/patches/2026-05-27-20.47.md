# Factory build BFF routes ignored by Git

**Date:** 2026-05-27 20:47
**Files:** diaweb/.gitignore, diaweb/frontend/app/api/cabinet/factory/buildings/[buildingKey]/resource/build/route.ts, diaweb/frontend/app/api/cabinet/factory/buildings/[buildingKey]/production/build/route.ts, diaweb/frontend/__tests__/app/api/cabinet/factory/route.test.ts
**Severity:** high

## Problem

Building any factory workshop on the dev site returned a Next.js HTML 404 for `POST /api/cabinet/factory/buildings/{building}/resource/build` instead of reaching the backend and returning a factory command response.

## Root Cause

The frontend had local Next App Router `build/route.ts` handlers for factory construction endpoints, but the repository `.gitignore` used a broad `build/` pattern. Git treated any nested directory named `build` as ignored, including valid App Router route segments such as `resource/build` and `production/build`. The files existed locally but were absent from `origin/dev`, so the deployed Next build did not include those API routes.

## Solution

Scoped the production build ignore rule to the repository root with `/build/`, allowing Next App Router route segments named `build` to be tracked. Added the missing resource and production factory build BFF route handlers to Git and extended the factory BFF route test so both construction endpoints are imported and verified.

## Prevention

- Avoid broad gitignore directory names that can collide with framework route segments.
- Add route tests that import every BFF endpoint introduced by feature code.
- During review, verify `git status --ignored` when source files exist locally but do not appear in normal status output.
