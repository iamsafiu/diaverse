# Shop Admin Mutation Responses Trigger MissingGreenlet

**Date:** 2026-04-26 23:34
**Files:** `diaverseapi/app/cabinet/shop/admin_service.py`, `diaverseapi/tests/test_cabinet_shop_admin.py`
**Severity:** high

## Problem

Staff shop admin `PATCH /v1/admin/shop/items/{id}` and `DELETE /v1/admin/shop/items/{id}` returned HTTP 500 after changing item status, sort order, or disabling a product. Production logs showed `sqlalchemy.exc.MissingGreenlet` while reading `offer.updated_at` inside `_offer_to_read()`.

## Root Cause

Shop admin mutations call `flush()` and then synchronously build Pydantic response models from SQLAlchemy ORM objects. Columns with server/onupdate behavior, especially `updated_at`, can be expired by SQLAlchemy after flush. Reading an expired ORM attribute performs implicit database IO. In async SQLAlchemy that implicit load happens outside `greenlet_spawn`, so serialization fails with `MissingGreenlet`.

## Solution

After mutation flushes, explicitly refresh the changed item/offer ORM instances before response serialization. The fix covers item updates, item disable operations including related offers, and XDV offer updates. A debug log with prefix `[FIX:shop-admin-mutation-refresh]` records refresh context and entity count without exposing user payloads.

## Prevention

- After async SQLAlchemy mutations that update server/default/onupdate columns, refresh ORM entities before reading them in synchronous response builders.
- Avoid response builders that can trigger implicit lazy loads from expired ORM attributes.
- Add mutation tests that assert changed ORM entities are refreshed before serialization.
