# Shared catalog image parity with shop storefront

**Date:** 2026-05-03 18:50
**Files:** diaverseapi/app/cabinet/item_catalog/providers.py, diaverseapi/app/cabinet/shop/image_resolver.py, diaverseapi/app/cabinet/shop/service.py, diaverseapi/tests/test_cabinet_item_catalog.py
**Severity:** medium

## Problem

Staff shop admin and other staff item catalogs showed incorrect images for pets and skins. The user-facing shop used storefront image resolution, while the shared catalog exposed smaller or stale icon fields.

## Root Cause

The shop storefront and shared item catalog had divergent image selection logic. Storefront pet rows resolved the default pet visual skin and normalized backend static URLs, but the shared catalog used `Character.icon` before `Character.image`, `PetSkinDef.icon` before `PetSkinDef.image`, and `PilotSkin.avatar` before `PilotSkin.image`.

## Solution

Moved storefront image resolution helpers into a shared `shop.image_resolver` module. The shop service now delegates to that resolver, and the item catalog providers use the same pet resolver plus `image`-first selection for pet and pilot skins.

## Prevention

Shared catalog providers should reuse domain display resolvers when a user-facing surface already defines canonical visual selection. Add regression tests that assert source image priority for every catalog-backed admin picker.
