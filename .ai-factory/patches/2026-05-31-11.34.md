# Shop free reward modal used stale PNG reward icons

**Date:** 2026-05-31 11:34
**Files:** diaverseapi/app/cabinet/shop/specials/service.py, diaverseapi/tests/test_cabinet_shop_specials.py
**Severity:** medium

## Problem

The production shop free reward modal had missing icons for many rewards. The active
`shop_free_daily` reward pool stored stale `snapshot_json.image_url` values such as
`brick.png`, `common.png`, and `rare_pet_4_evolution.png`, while production static assets
were available as `.webp`.

## Root Cause

`CabShopSpecialsService._catalog_snapshot()` merged persisted request snapshots after the
current catalog snapshot, so old admin-selected reward snapshots could override fresh catalog
images. Claim responses then trusted the stale snapshot image and returned URLs that resolved
to missing `/static/*.png` files.

## Solution

The service now resolves reward images from Advent/catalog reward metadata and prefers current
catalog images over stale request snapshot images. Existing XDV handling remains intact. A
debug log with prefix `[FIX:shop-free-reward-icons]` records stale image remaps when debug
logging is enabled. Regression tests cover stale reward pool snapshots and existing claim
responses with old image metadata.

Production data was also repaired by updating current `shop_free_daily` reward entry snapshots
and historical free reward claim snapshots from current resource, voucher, pilot-skin, and
virtual reward image sources.

## Prevention

- Treat persisted reward snapshots as display snapshots, not as authoritative asset sources.
- When source catalog assets are refreshed, make claim response builders prefer current catalog
  metadata or stable reward metadata mappings.
- Add tests for stale persisted snapshots whenever UI data is generated from cached JSONB fields.
