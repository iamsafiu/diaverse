# Diaweb build failed after shop rarity fields became required

**Date:** 2026-05-04 11:11
**Files:** diaweb/frontend/modules/shop/components/ShopHomeSpecials.tsx
**Severity:** high

## Problem

Docker build failed at `RUN npm run build`. The actual Next.js typecheck error
was that the synthetic `ShopCatalogItem` created in `ShopHomeSpecials.tsx` was
missing required `stars` and `rarity` fields.

## Root Cause

The merge from `evgeny-modules` made `ShopCatalogItem` require rarity metadata
for shop card visuals. Live catalog normalization and tests were updated, but
the specials payment selection path builds a catalog item manually and was not
updated with those new required fields.

## Solution

Added conservative defaults, `stars: 1` and `rarity: "rare"`, to the synthetic
specials item used by the payment modal. The modal does not render rarity UI,
so this satisfies the shared type without changing visible specials behavior.

## Prevention

When adding required fields to shared UI types, search for all manual object
construction sites and update synthetic test or modal bridge objects alongside
API normalization.
