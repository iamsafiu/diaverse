# Staff shop price OK button overflowed the next column

**Date:** 2026-05-24 16:04
**Files:** `diaweb/frontend/modules/staff-shop/components/ShopListingTable.tsx`
**Severity:** low

## Problem

The inline base-price editor in the staff shop table could overflow from the price column into the adjacent status column. The visible symptom was the `OK` button overlapping the next table column.

## Root Cause

The price column has a fixed percentage width in a `table-fixed` layout. At the table minimum width, the usable cell width after padding is smaller than the editor's hard `min-w-[132px]`, so the control could not shrink and spilled horizontally.

## Solution

The editor wrapper now uses `w-full max-w-[136px] min-w-0`, the input uses `flex-1 min-w-0`, and the currency/button widths were slightly reduced. The control now shrinks within the price cell instead of pushing the `OK` button into the next column.

## Prevention

Avoid fixed minimum widths inside fixed-table percentage columns unless the column width is guaranteed to exceed that minimum after padding. Prefer `min-w-0` and flexible children for compact inline controls.
