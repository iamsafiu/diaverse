# Factory production lines not selectable in web UI

**Date:** 2026-06-18 12:08
**Files:** diaweb/frontend/modules/factory/components/CompartmentScreen.tsx, diaweb/frontend/__tests__/modules/factory/FactoryCompartmentScreen.test.tsx, diaverseapi/app/factory/domain/policies.py, diaverseapi/app/factory/services/compartment_service.py, diaverseapi/app/factory/services/crafting_service.py, diaverseapi/app/factory/services/state_service.py, diaverseapi/app/factory/tests/test_crafting_service.py, diaverseapi/app/factory/tests/test_state_service.py
**Severity:** medium

## Problem

Factory production compartments at level 6 and 7 should expose 2 and 3 production lines respectively, but the web compartment screen still behaved as if only one line existed. The UI always sent `lineIndex: 1`, so users could not select or start crafts on unlocked additional lines. Existing persisted rows could also keep stale `lines_unlocked=1` even when the compartment level already implied more lines.

## Root Cause

The catalog and compartment upgrade service encoded the correct level-to-line mapping, but the frontend never rendered production line slots and hardcoded the craft request line index. Backend state serialization and craft validation trusted the persisted `lines_unlocked` column directly, so stale rows could keep showing and enforcing a single-line limit even after the level was 6 or 7.

## Solution

Added a backend helper for the expected line count by compartment level and used it during state serialization and craft validation as a non-destructive fallback over stale stored data. Added `[FIX:factory-lines]` warning logs when stale stored line counts are corrected at runtime.

Updated the web compartment screen to render selectable production line buttons, calculate active/running/queued jobs for the selected line, display the effective line count, and submit the selected `lineIndex` when starting a craft. Added targeted backend and frontend regression tests.

## Prevention

- Treat catalog-derived progression values as effective state when persisted rows can be stale from older releases.
- During review, search for hardcoded request defaults when adding multi-slot mechanics.
- Keep a regression test that selects a non-default line and asserts the API request includes that line index.
