# Restore Prodamus hosted choice flow and fee-free USD conversion

**Date:** 2026-04-23 10:14
**Files:** diaverseapi/app/cabinet/payments/quotes/prodamus.py, diaverseapi/app/cabinet/payments/prodamus/service.py, diaverseapi/tests/test_cabinet_prodamus_payments.py, diaverseapi/tests/test_cabinet_payment_fx.py
**Severity:** medium

## Problem

After exposing the Prodamus button and fixing the inflated USD amount, the hosted Prodamus page could skip the intended buyer-data step and open directly at payment-method selection or card payment. The Prodamus checkout also became too close to a forced USD invoice instead of preserving the previous multi-method hosted flow.

## Root Cause

The first USD fix removed Pay1Time's fee gross-up but changed Prodamus USD quotes to direct USD provider invoices. For this hosted Prodamus flow, that narrowed the provider-side behavior away from the previous RUB checkout with provider-side method choice. The checkout request also kept sending generated `customer_phone` and `customer_email`, which Prodamus documents as a way to skip the preliminary customer-data screen, and it passed `available_payment_methods`, which can restrict the provider method list.

## Solution

Prodamus USD quotes now use the shared USD/RUB FX snapshot but apply no Pay1Time fee, producing a RUB provider amount equal to the source USD price converted at the current rate. The hosted Prodamus request no longer sends generated buyer phone/email or `available_payment_methods`, so Prodamus collects buyer data and presents the full provider-side method choice. Tests now cover the fee-free conversion and assert the hosted request omits the fields that bypass or restrict the checkout flow.

## Prevention

- Keep provider quote strategies separate when they share FX data but not fee policy.
- Do not prefill Prodamus `customer_phone` for flows where the provider must collect buyer data.
- Do not pass `available_payment_methods` unless the product requirement is explicitly to restrict provider methods.
- Add regression tests for provider request fields, not only final amount/currency.
