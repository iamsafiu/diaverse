## Problem

The Advent analytics UI still exposed English labels in chart labels, heatmap cells,
repeat-run legends, and backend-generated insights. Recharts tooltips also inherited
CSS variables in a way that could render as transparent or low-contrast, and the
highest heatmap intensity used near-black text that was hard to read in the staff UI.

## Root Cause

The feature mixed backend-generated display strings with frontend presentation labels,
and some labels were left in English during the first implementation pass. Chart styling
relied on theme CSS variables inside Recharts inline/SVG contexts, where browser and
library defaults can fall back to transparent backgrounds or black text.

## Solution

Added explicit dark tooltip, label, and axis styles for analytics charts. Localized
frontend fallback labels for funnel steps, repeat-run metrics, heatmap cells, and
insights. Updated backend Advent analytics labels and empty-state messages to Russian
so API responses are localized as well. Added regression tests for localized labels and
readable heatmap text.

## Prevention

- Treat analytics API labels as user-visible copy and localize them in backend tests.
- Add frontend fallback localization when display labels may come from older backend data.
- Use explicit Recharts tooltip and SVG text colors instead of depending on CSS variables
  for chart overlays.
- Test that high-intensity visual states do not switch to unreadable dark text.
