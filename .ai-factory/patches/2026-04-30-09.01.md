# Notification popup hidden by cabinet topbar clipping

**Date:** 2026-04-30 09:01
**Files:** diaweb/frontend/modules/cabinet/components/CabinetTopbar.tsx, diaweb/frontend/modules/notifications/components/NotificationBell.tsx, diaweb/frontend/__tests__/modules/cabinet/CabinetTopbar.test.tsx, diaweb/frontend/__tests__/modules/notifications/NotificationBell.test.tsx
**Severity:** medium

## Problem

The cabinet notification popup was not visible after clicking the bell. The cabinet logo in the topbar also still navigated to the localized landing page, and the mobile popup needed to span the screen width.

## Root Cause

The topbar used `overflow-hidden`, so the absolutely positioned notification panel was clipped by the header bounds. The logo was implemented as a `Link` to `/{lang}`, which made ordinary topbar clicks on the brand leave the cabinet. The popup width was also anchored to the bell position on mobile, so it could not reliably occupy the viewport width.

## Solution

Changed the topbar to `overflow-visible` and raised its stacking context so the panel can render above cabinet content. Replaced the logo link with a non-navigating brand block. Added a mounted/visible split state for the notification panel so close transitions can play before unmounting. Added mobile-only fixed viewport positioning with full-screen width while preserving the existing desktop popup geometry.

## Prevention

When adding popovers inside framed shells, check ancestor overflow and stacking context before relying on z-index. For mobile popovers attached to compact toolbar buttons, prefer viewport-relative positioning when the expected layout is screen-width. Tests should cover non-navigation for decorative brand elements and animation/layout classes that protect popover visibility.
