# Fix: web-store Step Pass entitlements

## Problem

Users who bought Step Pass Pro in the web store could see premium Step Pass UI, but other domains still treated them as Basic/no Pro:

- exchange full-trade access denied
- pack slots stayed at the non-Pro limit
- some event/loot-box paths checked only `user_subscriptions`

Root cause: web-store Step Pass grants created/extended `personal_fitness_pass`, while several backend domains read only `user_subscriptions`.

## Changes

- Added `personal_fitness_pass.subscription_id` as an entitlement source in `SubscriptionMixin`.
- Updated exchange and raid subscription checks to include active personal Step Pass subscriptions.
- Updated bulk loot-box Pro detection to use `SubscriptionMixin`.
- Added web-store grant synchronization from personal Step Pass to `user_subscriptions`.
- Added idempotent Alembic backfill for active cabinet-shop personal Step Passes.
- Added focused tests for personal-pass entitlement lookup and user subscription synchronization.
