# Shop category blink and mobile scroll restore

**Date:** 2026-04-24 10:45
**Files:** diaweb frontend shop category route, shop home links, scroll restoration helper, shop tests
**Severity:** medium

## Problem

Opening a shop category on mobile or desktop caused the main shop icons to blink. Returning from a mobile category sent the user back to the top of the shop instead of preserving the position where the category was opened.

## Root Cause

The category route mounted a full `ShopHomePage` behind the modal/menu. That remounted all home images during category navigation, so the hidden/background home surface could visibly reload under the overlay. The category links also relied only on Next's `scroll={false}`, which was not enough once the `/shop` page was replaced by the `/shop/[category]` route tree and then mounted again.

## Solution

The category route now renders only the category surface plus a stable pending background layer, avoiding the duplicate home image tree. Category links save the current shop home `scrollY` into session storage before navigation, and `ShopHomePage` restores that position after remounting. The restore path logs development-only `[FIX:shop-scroll]` messages for save/restore troubleshooting.

## Prevention

Avoid mounting full image-heavy background pages behind modal routes unless the previous route tree is actually preserved by the router. For route-based overlays, store the opener scroll position before navigation and add a regression test that confirms return navigation restores it.
