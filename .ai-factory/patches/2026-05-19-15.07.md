# Club benefit posts inherited the generic Diaverse footer

**Date:** 2026-05-19 15:07
**Files:** `aibot/agents/writer.py`, `aibot/tests/test_agents.py`
**Severity:** medium

## Problem

Club benefit posts in the copywriting club tab included the generic Diaverse
channel footer with the Web2/Web3 disclaimer and app/founder links. That footer
is appropriate for common channel posts, but not for club-only benefit content.

## Root Cause

`generate_draft_content` normalized every LLM draft through
`_ensure_canonical_footer` without checking the draft content type. Club benefit
generation correctly passed `content_type=club_benefit`, but the writer did not
use that signal when deciding whether to append the canonical footer.

## Solution

Added content-type detection in `agents.writer` and disabled canonical footer
injection for `club_benefit` drafts. Club drafts also pass through
`_strip_existing_canonical_footer`, so a model-generated footer is removed before
storage. The prompt instruction is adjusted for club benefit drafts to explicitly
avoid the footer, disclaimer, and app links.

## Prevention

- Treat content type as part of writer formatting policy, not just topical
  guidance.
- Add regression tests when a channel-wide post rule has a domain-specific
  exception.
- For club copywriting, verify generated text at the storage boundary because
  LLM prompt instructions alone are not a reliable sanitizer.
