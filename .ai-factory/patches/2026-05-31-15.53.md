# Copywriting auto generation env flag

**Date:** 2026-05-31 15:53
**Files:** aibot/core/config.py, aibot/app/worker/main.py, aibot/.env.example, aibot/tests/test_worker_loop.py
**Severity:** medium

## Problem

Non-production copywriting runtimes could keep scheduling daily LLM generation jobs, spending provider tokens even when the environment should be idle.

## Root Cause

The worker loop always attempted to ensure daily run, daily fact, chat situation, and club benefit generation jobs on every poll. There was no environment-level feature flag to disable worker-created LLM jobs while leaving the worker available for manual queue processing and housekeeping.

## Solution

Added `COPYWRITING_AUTO_GENERATION_ENABLED` with a default of `true`. The worker now keeps TTL cleanup and normal queue polling active, but skips worker-created daily LLM scheduling when the flag is `false`. Added a regression test for the disabled path.

## Prevention

- Add env-level gates for cost-bearing scheduled automation.
- Keep manual queue processing separate from automatic scheduling controls.
- Cover runtime flags with worker loop tests so future scheduler changes cannot bypass the gate silently.
