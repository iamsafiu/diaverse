# Ops Agent user summary failed instead of continuing autonomously

**Date:** 2026-07-18 08:11
**Files:** `diaverseapi/app/ops_agent/contributions.py`, `aibot/app/ops_agent/orchestrator.py`, `aibot/app/ops_agent/prompting.py`, `aibot/app/ops_agent/codex_runner.py`, `aibot/core/config.py`, `aibot/docker-compose.prod.yml`
**Severity:** high

## Problem

A free-form Ops Agent request for user steps plus the `донат` flag ended with the canned response “Не удалось получить сводку пользователя. Повтори запрос позже.” The agent had selected the correct typed tool, but a backend HTTP 500 terminated the operator loop instead of being returned to Codex for autonomous diagnosis and recovery.

## Root Cause

The contribution attribution-gap query selected columns from both guest payment tables and used an implicit `outerjoin`. SQLAlchemy could not infer the left side and raised `InvalidRequestError` in production. Unit tests replaced the attribution-gap loader and therefore did not compile this real statement.

Separately, the Telegram orchestrator treated any typed-tool client error as a final user response. The Codex subprocess was configured and mounted read-only, so it could neither receive the tool failure as an observation nor repair workspace code.

## Solution

The backend query now explicitly starts from `CabGuestPendingEntitlement` with `select_from`, and a regression test compiles the complete attribution-gap query using the PostgreSQL dialect.

The operator loop now returns safe tool failure metadata (`reason_code`, `request_id`, and attempt count) to the same Codex thread. Codex is instructed to diagnose, repair, test, retry the tool, or finish through a verified read-only database fallback instead of asking the user to repeat later. The production Codex workspace and configurable sandbox now support write access.

## Prevention

- Compile every new SQLAlchemy statement that contains joins in a test; mocks that replace query loaders are insufficient.
- Treat action failures as tool observations inside the agent loop, not as final Telegram answers.
- Preserve request IDs and structured reason codes so Codex can correlate runtime errors without exposing secrets.
- Keep a bounded retry/fallback path and verify it with a first-call-fails/second-call-succeeds regression test.
