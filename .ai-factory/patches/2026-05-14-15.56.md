# Boost offers stayed unavailable after staff pricing

**Date:** 2026-05-14 15:56
**Files:** diaverseapi/app/cabinet/shop/admin_service.py, diaverseapi/tests/test_cabinet_shop_admin.py, diaverseapi/migrations/versions/20260514_publish_priced_boost_offers.py, diaweb/frontend/modules/staff-shop/components/ShopAdminPage.tsx, diaweb/frontend/__tests__/modules/staff-shop/ShopAdminPage.test.tsx
**Severity:** high

## Problem

Staff-entered USDT prices for boost shop offers were saved, but existing provider offers could remain `is_purchasable=false` with `availability_status=unavailable`. The storefront then rendered priced boosts as unavailable, so users could not buy them.

## Root Cause

The admin price update path normalized and persisted `display_price_amount`, but it did not update offer availability unless the caller explicitly sent those fields. The staff UI also sent only price and discount fields when editing an existing offer, so seeded unavailable offers stayed unavailable after pricing.

## Solution

The backend now auto-publishes priced external offers during `update_offer` when a positive USDT price is set and the caller did not explicitly send availability fields. The staff UI now sends offer availability flags derived from the updated item state for single and bulk listing price edits. A data migration publishes existing active storefront boost offers that already have positive USDT prices.

## Prevention

Cover admin offer price updates where a disabled provider offer becomes sellable, and where explicit unavailable flags are respected. Review future staff pricing flows for both price fields and sale-state fields.
