# Patch: stale staff access after role grant

## Summary

Fixed the staff access flow where recently granted employees could still be blocked by stale role claims in their existing cabinet access token.

## Root Cause

The production database had the correct RBAC state for the affected employees, including staff module access for `club` and `copywriting`. The frontend proxy and copywriting BFF still treated roles embedded in the access token as authoritative before consulting backend RBAC. Since cabinet access tokens are long-lived, existing sessions could keep `roles=["user"]` after a staff grant.

## Changes

- `diaweb/frontend/proxy.ts`: staff routes now require only an authenticated session at the proxy layer; module-level authorization is resolved by backend RBAC after staff hydration. Legacy staff-only cabinet routes keep token-role preflight.
- `diaweb/frontend/app/api/staff/copywriting/_auth.ts`: copywriting BFF now verifies the session token, then fetches `/v1/staff/access/me` and derives roles/permissions from the backend response instead of rejecting stale token roles early.
- `diaverseapi/app/cabinet/admin/service.py`: role revocation bumps `users.token_version`, invalidating old elevated access and refresh tokens after revoke.
