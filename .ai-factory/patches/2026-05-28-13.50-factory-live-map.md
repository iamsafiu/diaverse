# Patch: factory live map progress and collection

## Context

During factory UI fixes, the map had three coupled issues:

- the level map was stretched to the available viewport, so hotspot coordinates drifted from the visual grid;
- map bubbles showed static construction/production progress and did not expose resource collection;
- resource accrual was lazy-settled on warehouse commands, so the UI needed a live projection instead of waiting for the next server snapshot.

## Applied Pattern

- Keep the map canvas aspect-ratio locked and cap the map view to the intended mobile width.
- Derive live factory warehouse balances client-side from `last_accrual_at`, `stop_at`, the 10-hour cap, active resource-part level, and catalog generation rates.
- Use existing command mutations for direct map actions:
  - `transfer_to_storage` for resource/warehouse collection;
  - `collect_craft` for ready production jobs.
- Keep static map labels minimal; show only active process/resource data in bubbles.

## Follow-up Rule

For future factory map changes, do not use server snapshot quantities directly for visible pending resource accrual. Use a live projection helper or equivalent shared logic so timers, border progress, and displayed quantities move every second without forcing database writes.
