# Step Pass web-store month overlapped manual Pro grants

**Date:** 2026-06-02 14:38
**Files:** production data only; affected tables `user_subscriptions`, `cab_log_events`
**Severity:** medium

## Problem

A user's web-store Step Pass Pro purchase was paid and finalized, but support reported that the account still effectively had coverage only through the end of July after two manual Pro grants. The web-store month had not added a distinct future month of entitlement.

## Root Cause

The user already had manual Pro `user_subscriptions` for June and July. The web-store purchase created a `personal_fitness_pass` from 2026-06-01 to 2026-07-01, so it overlapped the already granted June period instead of becoming the next available month after the manual grants.

## Solution

Performed a targeted production backfill:

- Inserted one Pro `user_subscriptions` row for 2026-08-01 through 2026-08-31.
- Verified there was no existing August slot before insertion.
- Verified coverage after the fix: June manual Pro, July manual Pro, and August Pro compensation for the web-store purchase.
- Added a `cab_log_events` audit event tied to the original shop payment session.

## Prevention

- Step Pass shop fulfillment should layer paid months after existing active/future Pro subscription coverage instead of starting from `today` when overlapping grants exist.
- Add regression coverage for web-store Step Pass purchases when a user already has current/future Pro `user_subscriptions`.
- Staff runbooks should distinguish reward-row repair from entitlement-duration repair.
