# Factory map fullscreen chrome fix

**Date:** 2026-05-26 17:01
**Files:** diaweb/frontend/modules/cabinet/components/CabinetLayout.tsx, diaweb/frontend/modules/factory/components/FactoryScene.tsx, diaweb/frontend/modules/factory/components/FactoryShell.tsx, diaweb/frontend/modules/factory/components/FactoryHotspotLayer.tsx, diaweb/frontend/modules/factory/components/factoryScene.module.css
**Severity:** medium

## Problem

The factory main screen still behaved like a cabinet page: the cabinet topbar was visible, surrounding cabinet chrome reduced the available viewport, and the map canvas could be dragged internally. Workshop labels on the Russian route also displayed backend-provided English names.

## Root Cause

The new map-first factory view lived inside the generic cabinet layout, which always rendered topbar/footer/bottom navigation and bottom padding. At the scene level, the older manifest-driven pan implementation still wrapped the background and hotspots in a translated canvas. Labels reused backend titles instead of route-locale map copy.

## Solution

Added a dedicated fullscreen cabinet shell branch for the exact factory map route, removed the draggable scene canvas and pan handlers, made the level map fill the scene frame, removed the map-specific minimum height, and resolved Russian map labels/statuses in `FactoryHotspotLayer`.

## Prevention

- Treat game-like cabinet routes as fullscreen surfaces in the outer layout, not only inside the feature component.
- Avoid leaving interaction code from placeholder implementations when replacing a UX model.
- Add focused layout tests for cabinet chrome visibility on special routes.
