# Dead-letter copywriting jobs must surface as user-visible errors

## Problem

Daily recommendations, Daily Fact, and Club Benefit jobs could fail in the worker with a terminal `dead_letter` job while the domain record and UI card stayed in a queued/generating state.

Root causes:

- Top-level worker processors commit domain state only on success, so an exception rolls back intermediate `failed` updates.
- `generate_draft` child jobs were not reflected in Daily Fact / Club Benefit / Daily Run card status when the job was `dead_letter`.
- Daily Run scheduling reused the latest related job even when that job was `dead_letter` and no plan was produced.
- OpenAI `billing_hard_limit_reached` image errors were treated as generic retryable errors.

## Patch

- On terminal worker failure, mark related draft/run/fact/club-benefit entities failed in the worker failure session.
- Resolve `dead_letter` draft generation jobs as card `error` in Daily Fact, Club Benefit, and Daily Run responses.
- Include dead-letter job error text in response `status_reason` when the stored entity has no reason.
- Requeue Daily Run generation when the latest related run job is `dead_letter` and no plan exists.
- Treat OpenAI billing hard limit as a quota error and raise non-retryable `LLMProviderError` for image calls.

## Prevention

- For any queued/generating UI state, check both the domain entity status and the latest child job status.
- Do not rely on processor-session domain updates surviving exceptions; terminal job failure handling must persist the final user-visible state.
- Related-job idempotency should distinguish active/completed jobs from `dead_letter` jobs when the domain artifact was not created.
