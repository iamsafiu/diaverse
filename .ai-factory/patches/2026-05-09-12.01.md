# Asyncpg prepared statement failed on multi-command Alembic execute

**Date:** 2026-05-09 12:01
**Files:** diaverseapi/migrations/versions/20260509_giraffe_global_coefficient.py
**Severity:** high

## Problem

CI failed during `make migrate` with:

`asyncpg.exceptions.PostgresSyntaxError: cannot insert multiple commands into a prepared statement`

## Root Cause

The giraffe catalog seed migration sent two top-level SQL statements in one
`op.execute()` call:

- `DELETE FROM public.pet_skin_defs ...;`
- `WITH giraffe AS (...) INSERT INTO public.pet_skin_defs ...;`

The async Alembic environment uses the `asyncpg` driver, which prepares
statements and rejects multiple commands in one prepared statement.

## Solution

Split the delete and insert seed operations into two separate `op.execute()`
calls. Each call now contains exactly one top-level SQL statement.

## Prevention

For Alembic migrations running through `asyncpg`, never pack multiple
top-level SQL commands into one `op.execute()` or `conn.execute(text(...))`.
Use one execute call per statement, especially around seed/backfill blocks.
