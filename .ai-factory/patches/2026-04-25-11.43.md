# Advent modal card no longer owns scroll

**Date:** 2026-04-25 11:43
**Files:** `diaweb/frontend/modules/advent/advent.module.css`, `diaweb/frontend/__tests__/modules/advent/AdventCellModal.test.tsx`
**Severity:** medium

## Problem

After preserving page scroll for paid Advent cells, the modal card still had its own internal scroll area. This kept the payment flow split between nested scroll containers and made the modal feel broken on constrained screens.

## Root Cause

`.cellModalCard` still defined `max-height`, `overflow-y: auto`, and scroll containment styles. A mobile media override also reapplied a viewport-based `max-height`, so the card could remain its own scroll container even when document scroll was no longer locked.

## Solution

Removed the card-level height limits and internal overflow rules from the Advent modal CSS. The outer `.cellModalOverlay` remains the scrolling surface, so the card itself renders as one full panel. Added a regression test that reads the CSS source and fails if `.cellModalCard` gets `overflow-y: auto` or `max-height` again.

## Prevention

Avoid nested scroll containers for payment modals. When a modal needs to scroll, keep one owner for scrolling and add tests for the CSS rules that decide which layer owns it.
