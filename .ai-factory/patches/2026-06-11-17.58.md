# Alembic multiple heads after raid storage migration

**Date:** 2026-06-11 17:58
**Files:** `diaverseapi/migrations/versions/20260611_raid_daily_teams_storage.py`
**Severity:** high

## Problem

Production/CI migration failed on `alembic upgrade head` with:

`Multiple head revisions are present for given argument 'head'`

Alembic saw two heads after the raid storage commit reached `dev`: `raid_daily_teams_storage_20260611` and `skin_modifier_user_tz_20260611`.

## Root Cause

The raid storage migration was created before the latest remote `dev` migration was rebased in. During the code rebase the Python files merged cleanly, but Alembic metadata did not auto-adjust: both migrations still used `factory_catchup_20260610` as `down_revision`, creating two branches.

## Solution

Rebased the raid storage migration in the migration graph by changing its `down_revision` from `factory_catchup_20260610` to `skin_modifier_user_tz_20260611`.

Verified:

- `alembic heads` returns one head.
- `alembic upgrade skin_modifier_user_tz_20260611:raid_daily_teams_storage_20260611 --sql` generates SQL.
- `alembic upgrade factory_catchup_20260610:head --sql` walks through skin timezone migration and then raid storage migration.

## Prevention

After any rebase onto a branch that received migrations, always run `alembic heads` before pushing. If a feature migration was created against an older head, update its `down_revision` to the current `origin/dev` head before commit.
