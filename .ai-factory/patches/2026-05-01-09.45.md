# Fix shop special offer MissingGreenlet on create

**Date:** 2026-05-01 09:45
**Files:** diaverseapi/app/cabinet/shop/specials/service.py, diaverseapi/tests/test_cabinet_shop_specials.py
**Severity:** high

## Problem

Creating a shop special offer set via `POST /v1/admin/shop/specials/offer-sets` returned `500 Internal Server Error`.
Backend logs showed `sqlalchemy.exc.MissingGreenlet` in `CabShopSpecialsService._deactivate_offer_set_offers`.

## Root Cause

The service accessed `offer_set.slots` directly. For a newly flushed async SQLAlchemy ORM object, that relationship may be unloaded, so attribute access attempts lazy database IO outside the async greenlet context. Async SQLAlchemy does not allow this implicit lazy load and raises `MissingGreenlet`.

## Solution

Replaced direct relationship access with an explicit async `select(CabShopSpecialOfferSlot)` query by `offer_set_id`. Added debug logging with `[FIX:ShopSpecialsService._deactivate_offer_set_offers]` and a regression test that fails if the method touches the lazy `slots` relationship.

## Prevention

- In async SQLAlchemy services, do not rely on lazy relationship loads.
- Use explicit `select(...)` queries or eager loading such as `selectinload` before accessing relationships.
- Add regression tests around service methods that operate on freshly created ORM objects.
