# Fallback admin legacy pair replacement

**Date:** 2026-05-23 23:27
**Files:** diaverseapi/app/club/pairing.py, diaverseapi/app/club/repositories.py, diaverseapi/tests/test_club_service.py
**Severity:** medium

## Problem

When a member left the Telegram club chat, their remaining partner could be moved into a waiting solo group even though a fallback admin was configured. This happened when the fallback admin was already in an active legacy/manual pair recorded with buddy role `member` instead of `fallback`.

## Root Cause

The active fallback-pair lookup required `ClubBuddyMember.role = "fallback"`. Older/manual groups can contain the configured fallback admin as a normal buddy member while their membership has `pairing_mode = fallback_only`. The pairing service then saw the fallback admin as busy, but did not recognize the group as replaceable fallback occupancy.

## Solution

The repository now treats any active pair containing the configured fallback admin membership as the active fallback group. The replacement path still excludes the fallback admin by membership id, closes the old group, pairs the previous regular participant with the new regular participant, and leaves the fallback admin without an active buddy group. A focused regression test covers the legacy/manual role=`member` case.

## Prevention

Fallback behavior should key off the configured fallback membership id and current `pairing_mode`, not only the historical buddy-member role. Code reviews for pairing changes should check legacy/manual data shapes, not just newly created groups.
