# Shop route still redirected after navigation was restored

**Date:** 2026-04-30 09:17
**Files:** diaweb/frontend/app/[lang]/(cabinet)/shop/page.tsx, diaweb/frontend/modules/cabinet/components/CabinetTopbar.tsx, diaweb/frontend/modules/cabinet/components/BottomNav.tsx, diaweb/frontend/__tests__/app/cabinet-shop-page.test.ts, diaweb/frontend/__tests__/modules/cabinet/CabinetTopbar.test.tsx, diaweb/frontend/__tests__/modules/cabinet/BottomNav.test.tsx
**Severity:** medium

## Problem

The shop navigation item was visible, but clicking it still sent the user to Offers. The mobile navigation also placed Shop in the middle instead of the left position.

## Root Cause

The root `/[lang]/shop` page still contained an explicit `redirect("/{lang}/offers")`. Navigation items alone were restored, but the actual route entrypoint remained hidden. The tab arrays also ordered Offers before Shop.

## Solution

Changed the shop route page to load the dictionary and render `ShopHomePage`. Reordered cabinet topbar and bottom navigation so Shop is the first tab, followed by Offers and Profile. Updated route and navigation tests to assert that `/shop` renders, Shop links to `/ru/shop`, and Shop appears before Offers.

## Prevention

When re-enabling a feature route, verify both the navigation entry and the route entrypoint. Tests should cover redirects explicitly so hidden-route stubs cannot survive after the UI link is restored.
