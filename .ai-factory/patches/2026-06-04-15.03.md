# Category deal bundle cards lost contents

**Date:** 2026-06-04 15:03
**Files:** diaverseapi/app/cabinet/shop/category_deals/schemas.py, diaverseapi/app/cabinet/shop/category_deals/service.py, diaverseapi/tests/test_cabinet_shop_category_deals.py, diaweb/frontend/modules/shop/api.ts, diaweb/frontend/__tests__/modules/shop/shop-api.test.ts
**Severity:** medium

## Problem

Bundle cards rendered in the first six category-deal offer slots flipped to the back side and showed only the "Included" title. The bundle composition list was empty, while regular bundle cards outside the offer slots showed their contents correctly.

## Root Cause

The category-deals backend response used a reduced `ShopCategoryDealItemRead` DTO that did not include `bundle_items`. `_slot_to_read()` hydrated the shop item enough for ownership and purchase state, but then copied only basic item fields into the category-deal payload. The regular storefront path used a separate public bundle build path, so regular bundle cards had contents while category-deal bundle cards did not.

## Solution

Added `bundle_items` to the category-deal item schema and hydrated bundle slot contents from the same fulfillment-line based public bundle builder used by storefront cards. The frontend category-deal payload type now accepts `bundle_items`, so the existing catalog-item normalizer carries them into `item.bundleItems`.

## Prevention

When a new card variant reuses a catalog card component, verify that the API payload contains all data required by that component, not just the fields needed for purchase. Regression tests should cover both API normalization and backend DTO serialization for bundle-specific fields.
