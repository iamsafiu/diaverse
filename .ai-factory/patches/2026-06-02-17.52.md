# Factory life force early-access pet input fix

**Date:** 2026-06-02 17:52
**Files:** `diaverseapi/app/factory/services/crafting_service.py`, `diaverseapi/app/factory/tests/test_crafting_service.py`, `diaweb/frontend/modules/factory/components/CompartmentScreen.tsx`, `diaweb/frontend/__tests__/modules/factory/FactoryCompartmentScreen.test.tsx`
**Severity:** high

## Problem

Starting `life_force_workshop.rare_pet_life_force` in early access returned HTTP 200 with `status: blocked`. The error required `2.0000` `user_character_rare` while the concrete selected pet had only `1` available, so dismantling a selected rare pet could never start. The frontend also treated the HTTP success as a successful mutation and cleared the visible craft notice.

## Root Cause

Craft quote generation multiplied every input column by the combined craft cost multiplier, including inputs that resolve to selectable entities such as `input_rare_pet` and `selected_pet_fragment`. A concrete selected entity is not a stackable resource in this flow: one `user_character_id` represents exactly one pet, so an early-access cost multiplier of 2 created an impossible requirement.

The UI assumed transport success meant command success. Factory commands can return `status: blocked` with useful `errors` inside a 200 response, so the screen hid backend feedback.

## Solution

Added `_input_cost_multiplier` to preserve amount `1` for entity inputs with `requires_selection`, while leaving normal resource cost multipliers unchanged. The duration multiplier still applies to early access, so life force early access stays slower without requiring two concrete pets. The same helper is used for selected brick fragments.

Added a CompartmentScreen notice builder for successful HTTP responses with `status: blocked`, formatting insufficient-balance command errors into visible material lines such as `Rare pet: Need 2, have 1`.

## Prevention

- Do not apply generic numeric cost multipliers to selected entity inputs unless the UI/API can select multiple concrete entity IDs.
- Treat factory command `status` as the business result; HTTP 200 only confirms transport success.
- Cover early-access craft paths with concrete entity inputs in backend tests.
- Cover `status: blocked` command responses in frontend command UI tests.
