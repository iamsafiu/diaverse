# Club pairs tab exposed internal group codes

**Date:** 2026-05-19 21:45
**Files:** diaweb/frontend/modules/club/components/ClubPairsPanel.tsx, diaweb/frontend/__tests__/modules/club/ClubPairsPanel.test.tsx
**Severity:** medium

## Problem

The staff club pairs tab displayed internal buddy group codes such as `club-pair` or `club-d13e8af8` as the visible pair title. These codes are operational identifiers and should not be shown as the pair name.

## Root Cause

`ClubPairsPanel` rendered `pair.group_code` directly in `PairRow`. The API response already includes pair members with `telegram_username`, but the UI did not derive a public display title from those members.

## Solution

Pair titles are now derived from active buddy members. The UI prefers Telegram usernames, strips a leading `@`, joins pair members as `username + username`, and only falls back to a generic `Пара N` when no usable member label exists. The test now asserts that the visible title is `pair_one + pair_two` and that `club-pair` is not rendered.

## Prevention

Treat `group_code` as a technical field. Any user-facing pair title in staff UI or generated content should be derived from participants, not from internal identifiers.
