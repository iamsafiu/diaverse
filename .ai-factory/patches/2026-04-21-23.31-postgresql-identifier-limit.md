# Patch: PostgreSQL Identifier Limit In Alembic Indexes

## Context

During the Advent analytics implementation, the backend Docker migration step failed while applying `analytics_advent_001`.

Alembic attempted to create an index named:

```text
ix_cab_guest_pending_entitlements_advent_line_day_run_type_status_created_at
```

PostgreSQL rejects identifiers longer than 63 bytes, so SQLAlchemy raised:

```text
sqlalchemy.exc.IdentifierError: Identifier ... exceeds maximum length of 63 characters
```

The local checks had included `alembic heads`, `ruff`, tests, and Python compile checks, but not SQLAlchemy/PostgreSQL DDL compilation for the migration body.

## Root Cause

- A composite index name was generated from the full table/column intent without checking PostgreSQL's 63-byte identifier limit.
- `alembic heads` validates the revision graph only; it does not compile every `op.create_index(...)` operation.
- Python compile and Ruff do not catch database identifier length errors.

## Fix Applied

The long index name was shortened to a stable explicit name under the PostgreSQL limit:

```text
ix_cab_guest_pend_ent_adv_line_day_type_status_created
```

The name was updated in both:

- `diaverseapi/migrations/versions/analytics_advent_001_indexes.py`
- `diaverseapi/app/cabinet/guest/models.py`

The migration was then checked with:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade a1b2c3d4e5f9:analytics_advent_001 --sql
```

## Prevention

- When adding Alembic indexes, constraints, or explicit database object names for PostgreSQL, check that every explicit identifier is at most 63 characters.
- Prefer short but meaningful names for long composite indexes, for example abbreviating table segments while preserving intent.
- When a migration creates indexes/constraints, include an offline SQL compilation check in verification:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade <down_revision>:<new_revision> --sql
```

- Do not treat `alembic heads` as sufficient migration validation; it only confirms the revision graph.
