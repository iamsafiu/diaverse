# Preserve device bindings during auth logout

**Date:** 2026-04-23 14:39
**Files:** `diaverseapi/app/security/usecases.py`, `diaverseapi/app/security/api.py`, `diaverseapi/tests/test_logout_usecase.py`, `diaverseapi/tests/test_cabinet_auth.py`
**Severity:** high

## Problem

`POST /v1/auth/logout` from the web cabinet called `LogoutUseCase`, which deleted every `user_devices` row for the authenticated user. A normal web logout could therefore remove persistent mobile device bindings such as iPhone IDFV or Android ID rows.

## Root Cause

Logout session invalidation and persistent device identity were coupled in one use case. `LogoutUseCase.execute(user_id=...)` treated logout as account-wide device cleanup and issued `DELETE FROM user_devices WHERE user_id = :user_id`, even though cabinet logout already has a separate `CabinetAuthSession` revocation path and `user_devices` stores long-lived identity bindings.

## Solution

`LogoutUseCase` now preserves `user_devices` by default and only deletes a row when an explicit `device_id` scope is provided. The cabinet logout endpoint passes `device_id=None` deliberately. Regression tests cover both safe default behavior and the scoped-delete contract.

## Prevention

- Never delete persistent identity/linking rows from a session logout path without an explicit resource scope.
- Review logout code for account-wide predicates such as `WHERE user_id = ...` before merging.
- Keep tests that fail if logout returns to bulk-deleting `user_devices`.
- Prefer dedicated unlink/delete flows for device identity removal instead of overloading auth logout.
