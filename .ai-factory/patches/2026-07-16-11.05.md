# Factory pet skin cleanup, fractional warehouse display, and short-screen promo modals

**Date:** 2026-07-16 11:05
**Files:** diaverseapi/app/factory/infrastructure/inventory_gateway.py; diaverseapi/app/factory/services/state_service.py; diaverseapi/app/factory/tests/test_inventory_gateway.py; diaverseapi/app/factory/tests/test_state_service.py; diaverseapi/app/factory/tests/test_warehouse_service.py; diaweb/frontend/modules/factory/warehouseLive.ts; diaweb/frontend/modules/factory/components/FactoryWarehouseScreen.tsx; diaweb/frontend/__tests__/modules/factory/FactoryWarehouseLive.test.ts; diaweb/frontend/__tests__/modules/factory/FactoryWarehouseScreen.test.tsx; diaweb/frontend/modules/shop/components/shopPromoOfferModal.module.css; diaweb/frontend/__tests__/modules/shop/ShopPromoOfferModal.test.tsx; diaweb/frontend/modules/crypton/components/cryptonOfferModal.module.css; diaweb/frontend/__tests__/modules/crypton/CryptonOfferModal.test.tsx
**Severity:** medium

## Problem

Factory pet debits soft-deleted `UserCharacter` rows without freeing applied pet skin items. Factory warehouse storage also exposed fractional stored resource balances as transferable in the frontend even though inventory only accepts whole resource quantities. Separately, shop promo and Crypton offer modals could exceed short mobile/tablet viewport height, making close controls hard to reach.

## Root Cause

The factory inventory gateway reused soft-delete behavior but did not reuse the explicit pet-skin cleanup helper required for soft deletes. Warehouse storage kept raw `stored_quantity` as the only UI-visible value, so the frontend treated valid fractional persisted state as an actionable inventory transfer amount. Promo modal CSS relied on page-level overlay scrolling while the dialog itself had no viewport max-height and hid overflow.

## Solution

The pet debit path now calls `cleanup_skin_on_pet_delete` before setting `is_deleted=True`, after raid-lock validation. Factory state responses now include `stored_transferable_quantity` and `stored_retained_fraction`; the frontend displays and submits storage transfers from the transferable value, with a safe whole-number fallback for older backend responses. Promo modal CSS now bounds dialogs to `svh`/`dvh` viewport height, enables internal scrolling, and adds short-screen compact rules.

## Prevention

- Any future soft-delete path for pets should explicitly call the pet-skin cleanup helper.
- Backend state should expose separate raw and actionable quantities when persistence supports finer precision than downstream inventory.
- Modal and ad overlays should have dialog-level max-height, internal scroll, safe-area-aware close controls, and CSS regression checks for short viewports.
