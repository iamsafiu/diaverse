# WebCrypto BufferSource type mismatch in copywriting BFF auth

**Date:** 2026-06-02 09:49
**Files:** diaweb/frontend/app/api/staff/copywriting/_auth.ts
**Severity:** medium

## Problem

The Next.js production build failed in the staff copywriting BFF auth helper:
`Uint8Array<ArrayBufferLike>` was not assignable to WebCrypto's `BufferSource`
parameter in `crypto.subtle.verify`.

## Root Cause

`base64UrlDecode` wrapped a Node `Buffer` directly with `new Uint8Array(...)`.
With the current TypeScript and DOM lib types, that produces a typed array whose
backing buffer is inferred as `ArrayBufferLike`, which may include
`SharedArrayBuffer`. WebCrypto's `verify` signature requires an
`ArrayBufferView<ArrayBuffer>` or another concrete `BufferSource`.

## Solution

Decode the base64url signature into a Node `Buffer`, allocate a fresh
`Uint8Array` backed by a normal `ArrayBuffer`, copy the bytes into it, and return
that typed array. The cryptographic input bytes remain unchanged while the type
now satisfies WebCrypto.

## Prevention

- For WebCrypto inputs in Next.js server code, avoid passing typed arrays that
  are directly backed by Node `Buffer` memory when DOM typings require
  `ArrayBuffer`.
- Prefer a small decode helper that returns `Uint8Array<ArrayBuffer>` for JWT
  signatures and payload segments.
- Keep a build or typecheck regression around staff copywriting auth helpers.
