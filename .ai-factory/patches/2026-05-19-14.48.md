# Userbot peer invalid after club publish restart

**Date:** 2026-05-19 14:48
**Files:** `aibot/services/userbot_service.py`, `aibot/app/userbot/publish_processor.py`, `aibot/tests/test_userbot_service.py`
**Severity:** high

## Problem

Club post publishing failed with `Peer id invalid: -1003759564801` even though the userbot account was an administrator in the Telegram supergroup. Previously the same publish target had published successfully.

## Root Cause

Pyrogram can raise peer resolution failures as `ValueError`, not only `RPCError`. The userbot publish code had a dialog-scan fallback for missing private supergroup peers, but it only ran for `RPCError`. After a runtime restart, the club chat was missing from the persistent Pyrogram peer cache, so `ValueError: Peer id invalid` bypassed the fallback and the publish job moved directly to `dead_letter`.

## Solution

Handle `ValueError` with the same peer-invalid fallback path as `RPCError` in target preflight and send-time retry. Add structured warning fields for the error type and a controlled delivery failure when dialog refresh cannot resolve the peer. Also clear stale `error` and `partial_sent_messages` fields when a retried publish succeeds, so UI state does not show an old failure after `published`.

## Prevention

Cover Telegram userbot peer recovery tests for both `RPCError` and `ValueError`. During review, check Pyrogram exception handling against the actual exception type observed in production logs, not only the library's typed RPC hierarchy.
