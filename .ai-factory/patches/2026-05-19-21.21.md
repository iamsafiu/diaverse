# Club buddy leaderboard labels from group code

**Date:** 2026-05-19 21:21
**Files:** diaverseapi/app/club/leaderboards.py, diaverseapi/tests/test_club_leaderboards.py
**Severity:** medium

## Problem

Pair leaderboard entries used internal `club-...` buddy group codes as the public `label`. The same label is sent to aibot for leaderboard image generation and Telegram text, so users saw technical identifiers instead of the actual pair names.

## Root Cause

`ClubLeaderboardService._rank_buddy_entries` built each pair row from `ClubBuddyGroup` and used `group.group_code` as the label. The method did not resolve the active `ClubMembership` rows for the group members, so it had no access to `telegram_username` values when creating the snapshot payload.

## Solution

The buddy leaderboard builder now loads active memberships once, maps them by membership id, and resolves each buddy row label from member Telegram usernames. It strips a leading `@` for consistent display, joins pair names as `username + username`, and uses the configured fallback anchor username for waiting solo-buffer pairs.

## Prevention

Leaderboard snapshot payloads are user-facing content, not just database state. Review snapshot JSON fields that feed image prompts or Telegram text for public display semantics, and cover them with tests when internal ids or codes are available as tempting fallbacks.
