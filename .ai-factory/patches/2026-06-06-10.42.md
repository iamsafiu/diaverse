# Crypton modals overflowed viewport on short screens

**Date:** 2026-06-06 10:42
**Files:** frontend/modules/crypton/components/cryptonOfferModal.module.css, frontend/__tests__/modules/crypton/CryptonOfferModal.test.tsx
**Severity:** medium

## Problem

Crypton modal frames could become taller than the visible viewport on mobile
and short desktop screens. When the centered modal overflowed upward, the close
button in the top-right corner could move outside the visible screen.

## Root Cause

The primary offer modal used `min-height` without a matching `max-height`, and
its desktop content pane hid overflow. The request confirmation dialog also had
no dialog-level viewport cap. Both layouts assumed the modal content would fit
available screen height.

## Solution

Bounded the primary shell and request dialog with dynamic viewport-height
limits, made the inner content panes scroll vertically, and used safe centering
so overflowing content starts from the visible top instead of being clipped by
center alignment.

Added a regression test that reads the Crypton CSS module and verifies the
viewport bounds and internal scrolling rules remain present.

## Prevention

Modal containers should always combine viewport caps with an explicit scroll
owner. Code review for dialog CSS should check short desktop heights and mobile
safe-area behavior, not only standard desktop screenshots.
