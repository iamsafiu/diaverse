# Factory upgrade dialog scroll reset on parent rerender

**Date:** 2026-05-28 16:45
**Files:** `diaweb/frontend/modules/factory/hooks/useFactoryDialogFocusTrap.ts`, `diaweb/frontend/__tests__/modules/factory/FactoryDialogs.test.tsx`
**Severity:** medium

## Problem

On the factory level-upgrade page, the "Brick production" compartment upgrade dialog jumped back to the top while the user scrolled down.

## Root Cause

The shared factory dialog focus trap depended on the `onClose` callback. Several factory screens pass inline `onClose={() => ...}` handlers, and timer-driven parent rerenders create a new callback identity. Each callback change tore down and recreated the focus trap, which focused the first dialog control again. In a scrollable dialog, focusing the top close button reset the dialog scroll position.

## Solution

Kept the latest `onClose` callback in a ref updated by a small effect, removed `onClose` from the focus-trap setup effect dependencies, and focused dialog controls with `preventScroll`. Added a regression test that rerenders the compartment upgrade dialog with a new `onClose` and verifies the focused control stays stable.

## Prevention

- Focus trap setup effects should depend only on lifecycle inputs such as `enabled` and the container ref.
- Store volatile callbacks in refs when DOM listeners need the latest handler without reinstalling listeners.
- Use `focus({ preventScroll: true })` in scrollable overlays to avoid implicit scroll resets.
- Cover scrollable dialogs with rerender tests when parent screens have timers or live data refreshes.
