# Staff shop table toggles did not activate inactive rows

**Date:** 2026-05-24 15:56
**Files:** `diaweb/frontend/modules/staff-shop/components/ShopAdminPage.tsx`, `diaweb/frontend/modules/staff-shop/components/ShopListingTable.tsx`, `diaweb/frontend/modules/staff-shop/components/ShopListingEditor.tsx`, `diaweb/frontend/__tests__/modules/staff-shop/ShopAdminPage.test.tsx`
**Severity:** medium

## Problem

Staff shop rows with a valid positive USDT offer still appeared to reject `Маг.` and `Спец.` checkbox changes: the checkbox became checked optimistically, then returned to unchecked after the backend response. The UI also displayed noisy catalog override explanations for soft-unsellable rows.

## Root Cause

The table availability handlers sent only the per-column field, for example `{ is_storefront_visible: true }`. Rows that had previously been forced inactive still had `is_active=false`, and backend availability policy correctly keeps storefront/special flags false for inactive items.

## Solution

The frontend now builds availability toggle payloads centrally. When an admin enables storefront or special eligibility on an inactive row, the payload also includes `is_active: true`. The mutation mismatch logging now checks active-state mismatches as well. Visible catalog override explanations were removed from the listing table and editor while keeping hard-blocked toggle disabling.

## Prevention

Availability toggles that make a row externally visible must include the parent active state when the row is currently inactive. Regression tests should cover inactive rows with positive staff USDT offers for both storefront and special-offer toggles.
