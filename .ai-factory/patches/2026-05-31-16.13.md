# Dev-only copywriting generation kill switch

**Date:** 2026-05-31 16:13
**Files:** aibot/app/domain/generation_control.py, aibot/db/repositories/job_repo.py, aibot/app/api/main.py, aibot/app/worker/main.py, diaweb/frontend/app/api/staff/copywriting/_utils.ts, diaweb/frontend/.env.example
**Severity:** high

## Problem

Disabling copywriting generation only in `aibot` is not enough when dev and prod frontends point to the same shared copywriting API. A global API/worker flag would stop dev token spend but would also disable production generation.

## Root Cause

The manual staff generation path starts in `diaweb` BFF routes and then forwards to a shared `copywriting-api`. The first flag only controlled `aibot` automatic worker scheduling, so staff UI manual generation could still enqueue jobs.

## Solution

Added a global `aibot` kill switch for dedicated copywriting runtimes and a separate `diaweb` BFF gate for per-frontend disabling. Dev can now set `COPYWRITING_GENERATION_ENABLED=false` in the deployed `diaweb` environment to block manual generation requests before they reach the shared copywriting API, while production remains enabled.

## Prevention

- Confirm whether dev/prod share a runtime before applying environment-level kill switches.
- Put per-environment frontend gates at the BFF boundary when the upstream service is shared.
- Keep global service kill switches for emergency or dedicated non-production runtimes only.
