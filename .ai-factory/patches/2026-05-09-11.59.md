# Alembic multiple heads after concurrent dev migrations

**Date:** 2026-05-09 11:59
**Files:** diaverseapi/migrations/versions/20260509_merge_giraffe_and_fitness_pass_heads.py
**Severity:** high

## Problem

CI failed on `make migrate` with:

`Multiple head revisions are present for given argument 'head'`

## Root Cause

Two migrations were created from the same parent revision
`category_deal_durations_20260508`:

- `fix_fp_png_webp_20260508`
- `giraffe_global_coef_20260509`

After both reached `dev`, Alembic had two terminal revisions and
`alembic upgrade head` became ambiguous.

## Solution

Added a no-op Alembic merge migration with `down_revision` pointing to
both heads. This preserves already-pushed migration history and gives
Alembic a single new `head`.

## Prevention

Before pushing a migration after rebasing on shared branches, run:

- `python -m alembic heads`
- `python -m alembic upgrade <common_parent>:head --sql`

If more than one head is expected from concurrent migrations, add a merge
migration instead of editing already-pushed migration files.
