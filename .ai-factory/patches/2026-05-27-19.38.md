# Legendary mutagen catalog icon used wrong asset family

**Date:** 2026-05-27 19:38
**Files:** diaverseapi/app/cabinet/offers/advent/reward_images.py, diaverseapi/tests/test_cabinet_advent_reward_images.py
**Severity:** low

## Problem

The shared reward/item catalog displayed `mutagen_legendary` with `legendary_mutagen.webp`, an asset with a white background. Other mutagen catalog entries used the transparent catalog-style series: `common.webp`, `rare.webp`, and `epic.webp`.

## Root Cause

The legendary mutagen preset mixed two asset families. The old exchange-oriented `*_mutagen.webp` files are still present, but the staff catalog/advent image mapping had already moved common, rare, and epic mutagens to the clean catalog-style files. Legendary was the only remaining mismatch.

## Solution

Changed the shared reward image mapping for `mutagen_legendary` to `legendary.webp`. Added regression assertions for epic and legendary preset images and for rarity-based legendary mutagen resolution. Removed a duplicate test function in the same file so targeted Ruff checks pass.

## Prevention

- Keep rarity-based assets in one visual family when adding catalog presets.
- Add explicit tests for all newly added rarity tiers, not only the first/common tier.
- During review, compare both direct preset image mapping and metadata-based resolver output.
